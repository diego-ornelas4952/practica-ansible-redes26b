01 · Fundamentos

¿Qué es Ansible?

Una plataforma de automatización de código abierto que convierte tareas manuales de administración de sistemas en código limpio y reutilizable.

Infraestructura como Código
Describes qué estado quieres en archivos YAML legibles por humanos (Playbooks), en lugar de recordar decenas de comandos manuales.
100% Agentless (Sin Agentes)
No necesitas instalar ningún demonio o agente permanente en tus servidores. Ansible se conecta usando SSH estándar y Python.
Idempotencia garantizada
Puedes ejecutar el mismo Playbook 1 o 50 veces. Si el servidor ya cumple con el estado deseado, Ansible no realiza cambios innecesarios.
Escalable al instante
La misma lógica que configura 1 máquina virtual en tu red local puede orquestar cientos de servidores en la nube simultáneamente.

03 · Componentes

Los 3 pilares de nuestro proyecto

Con solo dos archivos en /Users/ornelas/practica-ansible controlamos toda la infraestructura.

1. Inventario
Archivo hosts.ini que agrupa los servidores por rol ([local] y [servidores_web]) y define sus credenciales e intérprete.
→ Qué máquinas controlar
2. Módulos y Ad-Hoc
Unidades de trabajo reutilizables (ping, file, copy, service, shell). Ideales para pruebas rápidas de una línea.
→ Acciones atómicas
3. Playbooks (YAML)
Orquestan múltiples tareas en orden, elevan privilegios con become: true y usan variables dinámicas (ansible_facts).
→ El plan completo
04 · Ingeniería Real

El reto técnico que resolvimos

Al conectar Ansible moderno con una VM Ubuntu 16.04.7 LTS descubrimos una incompatibilidad real de versiones y la solucionamos limpiamente.

El Problema: Python 3.5.2
Ubuntu 16.04 incluye Python 3.5 por defecto. Al ejecutar el comando ping, Ansible Core 2.21 falló con SyntaxError: invalid syntax porque usa f-strings (introducidas en Python 3.6+).

Además, los repositorios antiguos de Ubuntu 16.04 ya no ofrecen paquetes de Python modernos vía apt.
La Solución: Python 3.12 con uv
1. Instalamos Python 3.12 de forma aislada en la VM usando uv sin tocar el sistema base.

2. Configuramos ansible_python_interpreter en hosts.ini apuntando al nuevo binario.

3. Instalamos Nginx con shell + creates: /usr/sbin/nginx para mantener idempotencia sin depender de python3-apt.
05 · Implementación

Nuestro código en acción

~/practica-ansible/hosts.ini 
[local]
localhost ansible_connection=local ansible_python_interpreter=/opt/homebrew/bin/python3

[servidores_web]
ubuntu_vm ansible_host=192.168.1.222 ansible_user=ubuntu ansible_python_interpreter=/home/ubuntu/.local/share/uv/python/cpython-3.12-linux-x86_64-gnu/bin/python3.12
~/practica-ansible/playbook.yml 
---
- name: 2. Desplegar y configurar servidor web Nginx en Ubuntu Server
  hosts: servidores_web
  become: true

  tasks:
    - name: Instalar servidor web Nginx (si no está instalado)
      ansible.builtin.shell:
        cmd: DEBIAN_FRONTEND=noninteractive apt-get update && DEBIAN_FRONTEND=noninteractive apt-get install -y nginx
        creates: /usr/sbin/nginx

    - name: Desplegar página web personalizada con datos del servidor
      ansible.builtin.copy:
        dest: /var/www/html/index.html
        mode: '0644'
        content: | ... {{ ansible_facts['hostname'] }} ...

    - name: Asegurar que el servicio Nginx esté activo y habilitado al inicio
      ansible.builtin.service:
        name: nginx
        state: started
        enabled: true

06 · Despliegue Final

Servidor Nginx en producción

Con un solo comando (ansible-playbook -i hosts.ini playbook.yml -K), la VM queda sirviendo una web dinámica con sus propios ansible_facts.

1. Privilegios (become)
Usa sudo de forma segura solicitando la clave con -K al ejecutar.
2. Facts Dinámicos
Ansible inspecciona la VM antes de copiar el HTML e inyecta Hostname, OS, IP y Arquitectura.
3. Gestión de Servicios
Garantiza que nginx esté iniciado y habilitado automáticamente tras cada reinicio.
